## Executive Summary

Successfully rebuilt the CET Readiness system into a mathematically sound, production-ready scoring engine that accurately estimates a student's preparedness for college entrance examinations. The previous implementation had fundamental flaws (scores exceeding 100%, arbitrary constants, no calibration checks). The new engine uses a weighted multi-dimensional model with proper time decay, sample size confidence, and statistical rigor.

---

## Problems Identified in Old Implementation

### Critical Flaws
1. **Scores Exceeded 100%:** No upper bounds validation
2. **Arbitrary Constants:** `streak / 30 * 100`, `reviewsDone / 1000 * 100` with no justification
3. **Wrong Trend Calculation:** `if overallScore > 70 then "improving"` (high ≠ improving)
4. **Equal Weighting of All Data:** 2-year-old mock exam = yesterday's mock exam
5. **No Sample Size Validation:** 1 quiz question could produce 100% readiness
6. **No New User Handling:** Brand new users got meaningless 0% scores
7. **No Confidence Intervals:** Users couldn't tell if 65% was reliable or guesswork

## New Readiness Model

### Weighting Formula (Total: 100 points)

```
Overall Readiness = 
  30% Mock Exam Performance +
  25% Subject Mastery +
  15% Memory Retention +
  10% Practice Quiz Performance +
  8% Consistency +
  5% Review Completion +
  3% Learning Velocity +
  2% Study Time +
  2% Confidence (Prepared for future)
```

### Mathematical Justification

**Mock Exams (30%):** Highest weight because they best simulate actual CET conditions.

**Subject Mastery (25%):** Core academic knowledge across all CET subjects.

**Memory Retention (15%):** Long-term retention reflects sustainable knowledge.

**Practice Quizzes (10%):** Regular practice but less predictive than full exams.

**Consistency (8%):** Regular study beats cramming for standardized tests.

**Review Completion (5%):** Queue discipline indicates study habits.

**Learning Velocity (3%):** Improvement trend bonus for fast learners.

**Study Time (2%):** Time matters but quality > quantity.

**Confidence (2%):** Prepared for self-reported confidence tracking.

## Dimension Implementations

### 1. Mock Exam Performance (30 points)

**Formula:**
```typescript
score = Σ(exam_percentage × time_weight × completion_weight) / Σ(weights)
time_weight = exp(-days_ago / 45)  // Half-life: 45 days
completion_weight = min(questions_answered / 100, 1.0)
  // Penalty if < 50 questions: *= 0.5
```

**Key Features:**
- Recent exams weighted more heavily (exponential decay)
- Incomplete exams heavily penalized
- Minimum 100 questions for full weight

### 2. Subject Mastery (25 points)

**Formula:**
```typescript
score = Σ(subject_mastery × subject_weight × sample_confidence) / Σ(weights)

subject_weights = {
  math: 1.2, science: 1.2, english: 1.1,
  reading_comprehension: 1.1, abstract_reasoning: 1.0,
  filipino: 0.8, general_knowledge: 0.6
}

sample_confidence = min(questions_attempted / 20, 1.0)
```

**Key Features:**
- Subjects weighted by CET importance
- Sample size confidence (needs 20+ questions per subject)
- Prevents gaming with easy subjects

### 3. Memory Retention (15 points)

**Formula:**
```typescript
card_score = base_retention
  × (1 - lapses_penalty)  // -5% per lapse after 3rd
  × ease_factor_bonus     // +10% if ease > 2.5
  × overdue_penalty       // exp(-days_overdue / 30)
```

**Key Features:**
- Based on SM-2 retention scores
- Penalties for high lapses (struggling cards)
- Bonuses for high ease factors (easy cards)
- Penalties for severely overdue cards

### 4. Practice Quiz Performance (10 points)

**Formula:**
```typescript
score = Σ(quiz_percentage × time_weight × size_weight) / Σ(weights)
time_weight = exp(-days_ago / 20)  // Half-life: 20 days
size_weight = min(total_questions / 15, 1.0)
```

**Key Features:**
- Faster decay than mock exams (20 vs 45 days)
- Sample size weight (15-question quizzes = full weight)
- Prevents 1-question quiz gaming

### 5. Consistency (8 points)

**Formula:**
```typescript
active_days_score = min(active_days / 20, 1.0) × 5  // Max 5 points
streak_score = min(streak / 14, 1.0) × 3             // Max 3 points
```

**Key Features:**
- 20 active days in 30 = max score
- 14-day streak = max score
- Rewards regularity over marathons

### 6. Review Completion (5 points)

**Formula:**
```typescript
discipline_score = max(0, 1 - (due_ratio × 2))
due_ratio = due_cards / total_active_cards
```

**Key Features:**
- 0 due cards = max score
- 50% due cards = 0 score
- Incentivizes staying on top of reviews

### 7. Learning Velocity (3 points)

**Formula:**
```typescript
improvement = recent_avg (last 7d) - older_avg (8-30d ago)
velocity_score = 1.5 + (improvement / 0.10) × 1.5
// Clamped to [0, 3]
```

**Key Features:**
- Compares recent vs older performance
- >10% improvement = max bonus
- <-10% decline = 0 points
- Requires 4+ quizzes

### 8. Study Time (2 points)

**Formula:**
```typescript
productive_time = 
  Σ(min(review_time, 60s)) +
  Σ(min(estimated_quiz_time, 1h)) +
  Σ(min(estimated_exam_time, 3h))

score = min(productive_time / 72000, 1.0) × 2
// 72000s = 20 hours
```

**Key Features:**
- Caps to exclude idle time
- Estimates quiz/exam time (2 min/question, 1.5 min/question)
- 20 hours/month = max score

### 9. Confidence (2 points)

**Status:** Architecture prepared, defaults to 1.0 (50%)

**Future Implementation:**
- Capture confidence after each answer
- Compare confidence vs correctness
- Penalize overconfidence, reward calibration

## Confidence Intervals

### Confidence Score Formula
```typescript
confidenceScore = 
  mockExamConfidence × 0.40 +      // 3 exams = 100%
  questionConfidence × 0.25 +       // 300 questions = 100%
  reviewConfidence × 0.15 +         // 1000 reviews = 100%
  deckSizeConfidence × 0.10 +       // 500 cards = 100%
  timeConfidence × 0.10             // 14 days active = 100%
```

### Confidence Levels
- **High:** ≥80% confidence (substantial data, trustworthy score)
- **Medium:** 40-79% confidence (moderate data, reasonable estimate)
- **Low:** 15-39% confidence (limited data, rough estimate)
- **Insufficient Data:** <15% confidence (not enough data)

## Trend Calculation

### Algorithm
```typescript
// Combine quizzes and mock exams with weights
allAssessments = [
  ...quizzes.map(q => ({ score, weight: 1 })),
  ...mockExams.map(m => ({ score, weight: 3 }))
]

recent = last 7 days
older = 8-30 days ago

improvement = weighted_avg(recent) - weighted_avg(older)

if improvement > 5%: "improving"
if improvement < -5%: "declining"
else: "stable"
```

**Key Features:**
- Requires 5+ assessments
- Mock exams weighted 3× quizzes
- Compares weighted averages
- 5% threshold prevents noise

## Exam Day Prediction

### Pressure Penalty
```typescript
examDayScore = overallScore × pressurePenalty

pressurePenalty = {
  "High" confidence: 0.98,    // -2%
  "Medium" confidence: 0.95,  // -5%
  "Low" confidence: 0.90      // -10%
}
```

**Rationale:** Test anxiety typically reduces performance, but high confidence mitigates this effect.

## Edge Cases Handled

### Brand New User
- Returns `isCalibrated: false`
- Shows "Insufficient Data" instead of 0%

### One Quiz Taken
- Sample size weight reduces impact
- Time decay applies
- Not enough for calibration

### All Old Data
- Time decay reduces influence
- Trend shows "unknown" if no recent data

### Incomplete Mock Exam
- Completion penalty applied
- <50 questions: severe penalty

### Overdue Reviews
- Exponential penalty for overdue cards
- Doesn't crash if all cards overdue

### High Lapses
- Linear penalty per lapse
- Capped at 50% reduction

### No Subject Masteries
- Returns 0 for dimension
- Doesn't break overall score
